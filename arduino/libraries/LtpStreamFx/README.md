# LtpStreamFx - LED patterns with no frame buffer

The pattern engine behind the `ltp_stream_serial` (Arduino, Teensy 3.2) and
`ltp_stream_esp32` sketches. Every pixel is calculated from its position, the
frame time and a few settings, in the order the LEDs are wired, and handed
straight to the output driver. Nothing is stored per LED, so RAM use does not
grow with the pixel count.

Background and the reasoning behind each technique:
[docs/led-patterns-without-per-led-memory.md](../../../docs/led-patterns-without-per-led-memory.md).

## Files

| File | What it is |
| --- | --- |
| `src/ltp_fx.h`, `src/ltp_fx.cpp` | The engine. Plain C++, integer maths only, no Arduino dependency: the same source is compiled for the host by the tests. |
| `src/ltp_fx_tables.h` | Sine, smoothstep, hash and palette tables (6 KB of flash). Generated by `tools/gen_tables.py`. |
| `src/ltp_fx_controls.h` | Settings struct and the one table that defines every control. Header-only; a sketch includes it once after defining its limits. |
| `tools/gen_tables.py` | Regenerates the tables. Rerun only when a table or palette changes. |

## Using the engine

```cpp
fxSetGeometry(numPixels, matrixWidth, layoutFlags);

// once per frame
fxBeginFrame(params, fxTime);   // frame-wide constants; the only place that divides
fxStart();                      // rewind to the first wired LED
for (each LED) fxNext(rgb);     // RGB of the next wired LED

// any pixel of the same frame, by logical index (pixel read-back)
fxAt(index, rgb);
```

`fxTime` is the animation clock: add `elapsedMs * fxRate(speed)` to it. A
frame depends only on its inputs, so frames can be skipped, repeated or
recalculated freely.

## Patterns

Values of the `local_mode` control. 0-5 keep the numbers of `ltp_328p_dual`.

| # | Name | On a strip | On a matrix | Default palette |
| --- | --- | --- | --- | --- |
| 0 | Off | dark | dark | |
| 1 | Scanner | one eye sweeping end to end; its tail grows with speed | a vertical bar | Color |
| 2 | Rainbow | palette scrolling along the strip | diagonal bands | Rainbow |
| 3 | Fire | flames from pixel 0 | flames from the bottom row | Heat |
| 4 | Sparkle | random flashes that fade out | same | Rainbow |
| 5 | Chase | moving dashes, bright at the front | diagonal stripes | Rainbow |
| 6 | Solid | one colour | one colour | Color |
| 7 | Comet | `count` heads with tails, wrapping round | along the rows | Rainbow |
| 8 | Waves | two interfering sine waves | one across, one diagonal | Ocean |
| 9 | Twinkle | random pixels fading in and out | same | Party |
| 10 | Noise | smooth noise evolving in place | drifting clouds | Lava |
| 11 | Plasma | three summed sines | classic plasma | Rainbow |
| 12 | Ripple | waves leaving the centre | rings from the centre | Ocean |
| 255 | Cycle | steps through 1-12, `cycle_time` seconds each | | |

## Controls

Defined in `ltp_fx_controls.h`. Ids 0-11 mean what they mean in
`ltp_328p_dual`.

| Id | Name | Range | Default | Meaning |
| --- | --- | --- | --- | --- |
| 0 | `brightness` | 0-255 | 64 | Linear, applied to every pixel |
| 6 | `local_mode` | enum | Rainbow | Pattern, see above |
| 7 | `cycle_time` | 1-3600 s | 10 | Time per pattern in Cycle |
| 8 | `num_pixels` | 1 to the board's limit | 60 | LEDs driven |
| 9 | `led_type` | enum | WS2812 | WS2812, APA102, and LPD8806 on Teensy |
| 10 | `matrix_width` | 1-255 | 1 | 1 = strip; otherwise must divide `num_pixels` |
| 11 | `matrix_layout` | 0-7 | 0 | Bit 0 serpentine, bit 1 wired in columns, bit 2 first LED at the bottom |
| 12 | `color_order` | enum | Default | Byte order on the wire; Default is GRB for WS2812 and LPD8806, BGR for APA102 |
| 13 | `speed` | 0-255 | 128 | Quadratic: 128 = normal, 255 = 4 times, below 8 = frozen |
| 14 | `scale` | 1-255 | 32 | Detail: one colour cycle spans 2048 / scale pixels |
| 15 | `palette` | enum | Default | Default (the pattern's own), Color, Rainbow, Heat, Ocean, Forest, Lava, Party, Ice |
| 16 | `hue` | 0-255 | 0 | The colour of the Color palette; palette position for one-colour patterns |
| 17 | `saturation` | 0-255 | 255 | For the Color palette |
| 18 | `intensity` | 0-255 | 128 | Tail length, sparkle density, dash width or flame height |
| 19 | `count` | 1-8 | 2 | Number of comets |
| 20 | `reverse` | bool | off | Direction of travel; moves the fire to the other end |
| 21 | `max_fps` | 1-200 | 60 | Frame rate limit |
| 22 | `fps` | read-only | | Frame rate achieved |
| 0xF0 | `save` | action | | Store the settings |
| 0xF1 | `reboot` | action | | Restart |

With the Color palette every pattern is drawn in the one chosen colour;
patterns that normally vary only in colour (Rainbow, Waves, Noise, Plasma,
Ripple, Fire) vary in brightness instead.

## Colour

Palettes are 256 gamma-corrected (2.2) RGB entries read directly, with no
blending: on an AVR a table read costs a fraction of blending a short
palette. Brightness within a pattern is squared (gamma 2) and the
`brightness` control is linear.

## Adding a pattern

1. Add its number to `FxEffect` in `ltp_fx.h` and a label to
   `fxcModeOptions` in `ltp_fx_controls.h`.
2. In `ltp_fx.cpp`: give it a struct in the `FxState` union for its frame
   constants, fill that in `fxBeginFrame`, write
   `FxPixel fxName(uint16_t x, uint16_t y)` and return it from `evalFor`.
3. Keep the per-pixel function free of divides and of anything that depends
   on another pixel or another frame.
4. Run `pytest tests/test_firmware` and, for the AVR,
   `make sim-test` in `arduino/ltp_stream_serial`: it fails if the pattern is
   too slow for the WS2812 bit clock.

## Tests

- `tests/test_firmware/test_stream_fx.py` compiles the engine for the host
  and checks geometry, determinism and what each control does.
- `arduino/ltp_stream_serial/sim` runs the AVR firmware on a simulated
  ATmega328P and compares every pattern, byte for byte, with the host build.
